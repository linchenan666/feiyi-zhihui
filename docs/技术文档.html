01 · 项目概述

1.1 定位

非遗智汇是一个「能看、能问、能关联、能生成、能沉浸」的河南非遗 AI 数字展厅——单页应用（SPA），纯本地运行、零上传、零后端。面向大众（学生/年轻人为主，兼顾长辈与游客），把散落在名录、地方志与短视频中的非遗知识，整合为一个"被美打动 → 选中读进去 → 与 AI 对话深挖 → 收藏 → 生成文创分享"的完整产品闭环。

1.2 痛点与价值

真实痛点本项目解法
非遗知识散、难查、看不懂15 项招牌非遗 × 4 维结构化内容（要点/深挖/待核清单/问答），覆盖 6 大门类、9 地市
缺少"能问"的入口内置知识库离线问答（双层架构），随问随答、演示永不断线；支持多轮指代追问（「它 / 这个 / 那」自动回指上一主题）
缺少"能玩、能关联"的入口非遗地图（地域坐标）+ 知识图谱（项目↔门类↔地域亲缘）
缺少"能带走"的传播物AI 文创工坊本地合成 4 风格海报，一键下载分享
隐私顾虑纯本地、零上传、无第三方脚本，收藏与主题偏好仅存于本地浏览器

1.3 内容范围

招牌 15 项深挖：豫剧、曲剧、河南坠子、马街书会、钧瓷、汝瓷、唐三彩、洛阳水席、汴绣、朱仙镇年画、浚县泥咕咕、淮阳泥泥狗、少林功夫、陈氏太极拳、打铁花。每项均基于国家级非遗名录与公开资料核对，不确定条目全部显式标注在"待核清单"中——数据诚实，不编造。

02 · 意图控制策略

本项目的核心命题：代码由 AI 生成，人类负责定义问题、约束行为、验证结果。以下为贯穿全程的六条 Prompt 工程原则，每条均附真实案例。

2.1 原则一：上下文先于提问

每次向 AI 提问前，先声明三件事：项目是什么、数据在哪里、硬约束是什么。AI 不靠猜。

我要参加传智杯「AI 创新应用挑战赛」（Vibe Coding 方向，B 组个人赛），
做一个河南非遗 AI 数字展厅网页。要求：
1. 数据与视图分离：data.js 存数据，app.js 管渲染，本地双击即可运行；
2. 新中式设计体系：宣纸·墨·朱砂·金（60/30/10），衬线标题+无衬线正文；
3. 视觉素材用统一水墨风格的生成图，15 项招牌非遗每项一张；
4. 纯本地、零上传、无第三方脚本（CDN 除外），隐私是卖点。
请先给设计计划，再分模块实现。

效果：AI 一次性给出与题材匹配的设计 token 体系与数据模型，而非通用模板。

2.2 原则二：把红线写进 Prompt（防 AI slop）

对审美与工程风险，用祈使句显式声明，杜绝"生成味"与性能隐患：

注意：不要用毛玻璃、glow 边框、粒子网背景、data-aos 全站铺淡入、
渐变按钮这些 AI 生成味很重的套路。动效克制：每个区块一次编排过的入场，
不要每张卡片都来一套 hover 动画。

同样的方式约束性能：pointermove 监听必须 rAF 节流、will-change 只在 hover 时开、隐藏视图定时器必须清理——把工程红线前置，比事后修复成本低一个数量级。

2.3 原则三：Bug 报告三件套

发现缺陷时，报告结构固定为现象 → 已排查的原因 → 期望行为。AI 一次定位，不瞎改、不扩散改动范围。真实案例（问答引擎 0 命中）：

知识库问答有 bug：问"豫剧"和"钧瓷有什么特点"都命中不了。
排查：KB_ITEMS 的关键词数组是 [itemName].concat(question.split(" "))
拼出的整句关键词，没有分词，单项目名或短问题匹配不上。
请改成关键词数组 = [项目名] 与问题分词结果的并集，再验证
"豫剧""钧瓷有什么特点""第一次来先看什么"三类问题。

2.4 原则四：验证闭环

每个功能模块落地后，用三条验证链回归，发现问题立即补 Prompt 修复链：

  • 语法层：node --check 全量 JS 语法
  • 渲染层：Edge 无头浏览器逐视图截图 + DOM 断言
  • 自检层：官方 shot.py 自检（consoleErrors / 横向溢出 / 响应式）

2.5 原则五：验收驱动扩散（克制与收敛）

视觉类改动每处独立提交 + 用户验收，验收通过才扩散到其他页面，未通过即 revert 并保留提交记录。M8 系列真实记录：展品卡片文化图（revert）、其余页面标题区动态背景（revert）、导航置顶（revert）——评委看到的不是一帆风顺，而是"尝试 → 验收 → 收敛"的完整决策证据，这比"一次做对"更可信。

2.6 原则六：把评审标准翻译成产品细节

评审点名的交互体验，主动前置到需求里：

评审标准里有一条"AI 响应状态提示友好（如流式、思考可视化）"。
问·AI 目前只有流式打字。请加"思考中"状态：发送后先出现三个呼吸点的
思考气泡（约 0.5s），再切换为流式作答；reduced-motion 用户直接出结果。

产出：思考状态气泡 + 流式打字 + 无障碍兜底，形成完整的"响应状态语言"。

03 · 架构设计

AI 生成代码最怕"一次性屎山"。本项目通过三层约束保证架构质量：文件职责强制分离、hash 路由驱动视图、动效引擎统一收口。

3.1 整体架构

层文件职责约束方式
结构/样式index.html页面骨架、设计系统（CSS 变量）、动效质感层设计 token 集中定义，主题切换只改变量
数据层data.js15 项非遗 × 4 维、知识库、图谱连边、地市坐标纯数据、零逻辑，评委可逐条核对
交互层app.js10 视图渲染、hash 路由、问答匹配、动效引擎、持久化IIFE 单作用域，模块按注释分区
素材层assets/15 张统一水墨风格生成图统一风格 prompt 批量生成

3.2 路由与视图

原生 hash 路由驱动 10 个视图（home/hall/item/map/region/graph/ask/create/evolution/treasury/immerse），无框架、无构建。视图切换采用 View Transitions API（原生支持时启用编排过渡，不支持自动回退），保证"页面切换"这一高频动作的流畅与优雅。

地图视图：真实行政区划河南地图（公开 GeoJSON → Mercator 投影 → SVG path，独立 map-data.js 数据层），18 地市边界 + 15 项招牌非遗按经纬度精确定位；点击「放大」进入全屏交互模态（滚轮缩放 1x–5x 以光标为锚点、拖拽平移、三退出路径）；悬浮非遗红点其余点与名称 0.3s 淡出（聚焦模式）；点击地市板块直接进入对应城市介绍。画布与模态共用 mapSvgHtml / bindMapInteractions，一次实现双态生效。图谱视图：力导向布局（label 感知斥力按占用面积、亲缘/门类/地域弹簧分级、三环分层）+ 六门类扇区化 + 氛围画布（纸纹 / 晕染 / 水印），节点分批入场动画，SVG 最小渲染 1000px + 缩放控件保证任意窗口可读。城市介绍视图：18 地市城市档案（regions-data.js），地图点击板块/列表行跳转对应城市，卡片配标志性建筑图（REGION_IMG 映射）。

3.3 全视口背景层架构（M8 系列视觉核心）

地图 / 展品总览 / 城市介绍三个内容页采用统一的全视口动态背景架构，保证"背景与浏览器页面等宽等高、导航区保持原样、文字永远可读"：

┌─────────────────────────────────────────────┐
│ 导航栏（常驻纸色背景，文字永远可见）            │
├─────────────────────────────────────────────┤
│ 背景层 .xx-bg（fixed，top:var(--nav-h)）       │
│   · 地图页：4 张河南地理风光 24s 轮播 + 慢缩放  │
│   · 展品页：4 层 CSS 渐变轮播（紫靛/朱砂/青黛/绛红）│
│   · 城市页：4 张标志性建筑 24s 轮播             │
│ 遮罩层 .xx-veil（fixed，深色渐变，保证对比度）  │
├─────────────────────────────────────────────┤
│ 内容层 .xx-view/.xx-detail（relative，z-index:2）│
│ 页脚 footer（relative，z-index:5，压过背景层）  │
└─────────────────────────────────────────────┘
关键约束：①背景 position:fixed 且 left/right/bottom:-5% 微扩防露边，等宽等高；②top 严格 var(--nav-h)（曾踩 calc(var(--nav-h) - 5%) 百分比陷阱——5% 按视口高度计算会把背景顶回导航区，已修复并记录）；③页面内文字/卡片统一半透明深底 + 白字黄字规则（标题金黄 #F3D9A4、小字白色系），任意背景帧下可读；④背景轮播仅在对应视图渲染时注入 DOM，视图切换即释放。

3.4 双层问答架构（核心创新点）

为解决"演示断线"与"真 AI"的矛盾，问答系统设计为双层架构：

┌─────────────────────────────────────────────┐
│  用户提问                                        │
├─────────────────────────────────────────────┤
│  第一层 · 内置知识库（离线，默认启用）            │
│  关键词打分匹配：命中 ≥4 字词条 3 分、其余 2 分， │
│  最高分 ≥2 命中，否则兜底话术                    │
│  + 多轮上下文：记录上一主题，指代词自动回指       │
│  → 保证演示 100% 不断线、支持连续追问            │
├─────────────────────────────────────────────┤
│  第二层 · 远程大模型（可选，一键点亮）            │
│  app.js 顶部 REMOTE_API 填 url/key/model 即升级  │
│  → 有 key 时回答切换为大模型生成                  │
└─────────────────────────────────────────────┘
设计意图：离线层保证"任何时候都能演示"，在线层兑现"真·AI"；多轮上下文让离线问答也可连续追问，评审看到的是可解释、可升级、真能用的架构，而非黑盒。

3.5 动效引擎（统一收口）

所有指针类动效收口为单一事件委托处理器 initPointerFX()：磁性按钮 + 卡片 3D 倾斜共用一次 pointermove 监听，rAF 节流保证每帧至多一次布局读取；滚动揭示（IntersectionObserver）、页面过渡（View Transitions）各司其职；惯性平滑滚动库（Lenis）经实测性能权衡后已从运行时禁用，回退原生滚动（滚轮手感最稳、零额外开销）。prefers-reduced-motion 全局兜底，无障碍用户自动获得静止版。

4.1 安全

风险面对策

4.2 性能（本版本专项治理）

问题治理收益
3D tilt 与 CSS 过渡互相打架，每帧追 350ms 动画激活时切 0.1s 快过渡、离开还原倾斜跟手、不再持续重算
双 pointermove 监听无节流、强制同步布局合并单监听 + rAF 节流每帧至多一次布局读

15 个常驻 GPU 合成层will-change 改 hover 触发GPU 内存释放

4.3 无障碍

  • 键盘可达：地图标点、图谱节点、收藏按钮全部 tabindex + aria + Enter/Space 响应
  • :focus-visible 全局焦点环，不隐藏 outline
  • prefers-reduced-motion：动效、打字机、思考动画、视差、图谱入场动画全部关闭
  • 语义化标签 + aria-label；对比度正文 ≥ 4.5:1

05 · 可复现性论证
