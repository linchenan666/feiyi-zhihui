01 · 项目概述

1.1 定位

非遗智汇是一个「能看、能问、能关联、能生成、能沉浸」的河南非遗 AI 数字展厅——单页应用（SPA），纯本地运行、零上传、零后端。面向大众（学生/年轻人为主，兼顾长辈与游客），把散落在名录、地方志与短视频中的非遗知识，整合为一个"被美打动 → 选中读进去 → 与 AI 对话深挖 → 收藏 → 生成文创分享"的完整产品闭环。

1.2 痛点与价值

真实痛点本项目解法
非遗知识散、难查、看不懂15 项招牌非遗 × 4 维结构化内容（要点/深挖/待核清单/问答），覆盖 6 大门类、10 地市
缺少"能问"的入口内置知识库离线问答（双层架构），随问随答、演示永不断线
缺少"能玩、能关联"的入口非遗地图（地域坐标）+ 知识图谱（项目↔门类↔地域亲缘）
缺少"能带走"的传播物AI 文创工坊本地合成 4 风格海报，一键下载分享
隐私顾虑纯本地、零上传、无第三方脚本，收藏与主题偏好仅存于本地浏览器

1.3 内容范围

招牌 15 项深挖：豫剧、曲剧、河南坠子、马街书会、钧瓷、汝瓷、唐三彩、洛阳水席、汴绣、朱仙镇年画、浚县泥咕咕、淮阳泥泥狗、少林功夫、陈氏太极拳、打铁花。每项均基于国家级非遗名录与公开资料核对，不确定条目全部显式标注在"待核清单"中——数据诚实，不编造。

02 · 意图控制策略

本项目的核心命题：代码由 AI 生成，人类负责定义问题、约束行为、验证结果。以下为贯穿全程的五条 Prompt 工程原则，每条均附真实案例。

2.1 原则一：上下文先于提问

每次向 AI 提问前，先声明三件事：项目是什么、数据在哪里、硬约束是什么。AI 不靠猜。

我要参加传智杯「AI 创新应用挑战赛」（Vibe Coding 方向，B 组个人赛），
做一个河南非遗 AI 数字展厅网页。要求：
1. 数据与视图分离：data.js 存数据，app.js 管渲染，本地双击即可运行；
2. 新中式设计体系：宣纸·墨·朱砂·金（60/30/10），衬线标题+无衬线正文；
3. 视觉素材用统一水墨风格的生成图，15 项招牌非遗每项一张；
4. 纯本地、零上传、无第三方脚本（CDN 除外），隐私是卖点。
请先给设计计划，再分模块实现。

效果：AI 一次性给出与题材匹配的设计 token 体系与数据模型，而非通用模板。

2.2 原则二：把红线写进 Prompt（防 AI slop）

对审美与工程风险，用祈使句显式声明，杜绝"生成味"与性能隐患：

注意：不要用毛玻璃、glow 边框、粒子网背景、data-aos 全站铺淡入、
渐变按钮这些 AI 生成味很重的套路。动效克制：每个区块一次编排过的入场，
不要每张卡片都来一套 hover 动画。

同样的方式约束性能：pointermove 监听必须 rAF 节流、will-change 只在 hover 时开、隐藏视图定时器必须清理——把工程红线前置，比事后修复成本低一个数量级。

2.3 原则三：Bug 报告三件套

发现缺陷时，报告结构固定为现象 → 已排查的原因 → 期望行为。AI 一次定位，不瞎改、不扩散改动范围。真实案例（问答引擎 0 命中）：

知识库问答有 bug：问"豫剧"和"钧瓷有什么特点"都命中不了。
排查：KB_ITEMS 的关键词数组是 [itemName].concat(question.split(" "))
拼出的整句关键词，没有分词，单项目名或短问题匹配不上。
请改成关键词数组 = [项目名] 与问题分词结果的并集，再验证
"豫剧""钧瓷有什么特点""第一次来先看什么"三类问题。

2.4 原则四：验证闭环

每个功能模块落地后，用三条验证链回归，发现问题立即补 Prompt 修复链：

  • 语法层：node --check 全量 JS 语法
  • 渲染层：Edge 无头浏览器逐视图截图 + DOM 断言
  • 自检层：官方 shot.py 自检（consoleErrors / 横向溢出 / 响应式）

2.5 原则五：把评审标准翻译成产品细节

评审点名的交互体验，主动前置到需求里：

评审标准里有一条"AI 响应状态提示友好（如流式、思考可视化）"。
问·AI 目前只有流式打字。请加"思考中"状态：发送后先出现三个呼吸点的
思考气泡（约 0.5s），再切换为流式作答；reduced-motion 用户直接出结果。

产出：思考状态气泡 + 流式打字 + 无障碍兜底，形成完整的"响应状态语言"。

03 · 架构设计

AI 生成代码最怕"一次性屎山"。本项目通过三层约束保证架构质量：文件职责强制分离、hash 路由驱动视图、动效引擎统一收口。

3.1 整体架构

层文件职责约束方式
结构/样式index.html页面骨架、设计系统（CSS 变量）、动效质感层设计 token 集中定义，主题切换只改变量
数据层data.js15 项非遗 × 4 维、知识库、图谱连边、地市坐标纯数据、零逻辑，评委可逐条核对
交互层app.js8 视图渲染、hash 路由、问答匹配、动效引擎、持久化IIFE 单作用域，模块按注释分区
素材层assets/16 张统一水墨风格生成图统一风格 prompt 批量生成

3.2 路由与视图

原生 hash 路由驱动 8 个视图（home/hall/item/map/graph/ask/create/immerse），无框架、无构建。视图切换采用 View Transitions API（原生支持时启用编排过渡，不支持自动回退），保证"页面切换"这一高频动作的流畅与优雅。

3.3 双层问答架构（核心创新点）

为解决"演示断线"与"真 AI"的矛盾，问答系统设计为双层架构：

┌─────────────────────────────────────────────┐
│  用户提问                                        │
├─────────────────────────────────────────────┤
│  第一层 · 内置知识库（离线，默认启用）            │
│  关键词打分匹配：命中 ≥4 字词条 3 分、其余 2 分， │
│  最高分 ≥2 命中，否则兜底话术                    │
│  → 保证演示 100% 不断线、零网络依赖              │
├─────────────────────────────────────────────┤
│  第二层 · 远程大模型（可选，一键点亮）            │
│  app.js 顶部 REMOTE_API 填 url/key/model 即升级  │
│  → 有 key 时回答切换为大模型生成                  │
└─────────────────────────────────────────────┘
设计意图：离线层保证"任何时候都能演示"，在线层兑现"真·AI"；评审看到的是可解释、可升级的架构，而非黑盒。

3.4 动效引擎（统一收口）

所有指针类动效收口为单一事件委托处理器 initPointerFX()：磁性按钮 + 卡片 3D 倾斜共用一次 pointermove 监听，rAF 节流保证每帧至多一次布局读取；滚动揭示（IntersectionObserver）、页面过渡（View Transitions）、惯性滚动（Lenis，含隐藏时暂停）各司其职。prefers-reduced-motion 全局兜底，无障碍用户自动获得静止版。

04 · 工程质量

4.1 安全

风险面对策
XSS（所有动态内容经 innerHTML 注入）统一 esc() 转义：& < > "；所有用户输入、数据字段注入前必过
第三方脚本供应链仅 2 个静态 CDN（字体镜像 + Lenis），零追踪、零遥测；断网自动降级
本地存储localStorage 读写全部 try/catch，隐私数据仅存本机
API 密钥泄露REMOTE_API 默认关闭，文档明确"请勿提交密钥到公开仓库"

4.2 性能（本版本专项治理）

问题治理收益
3D tilt 与 CSS 过渡互相打架，每帧追 350ms 动画激活时切 0.1s 快过渡、离开还原倾斜跟手、不再持续重算
双 pointermove 监听无节流、强制同步布局合并单监听 + rAF 节流每帧至多一次布局读
毛玻璃滚动逐帧重绘移除 backdrop-filter，提高背景不透明度滚动不再卡顿
15 个常驻 GPU 合成层will-change 改 hover 触发GPU 内存释放
Lenis 后台空转 / 定时器泄漏visibilitychange 暂停；视图切换即清理空闲 CPU 归零

4.3 无障碍

  • 键盘可达：地图标点、图谱节点、收藏按钮全部 tabindex + aria + Enter/Space 响应
  • :focus-visible 全局焦点环，不隐藏 outline
  • prefers-reduced-motion：动效、打字机、思考动画、视差全部关闭
  • 语义化标签 + aria-label；对比度正文 ≥ 4.5:1

05 · 可复现性论证

本赛项对"过程可复现"的权重为 25%，本项目将其作为第一工程约束来设计。

5.1 一键复现（10 分钟极速指南）

环境：任意现代浏览器 + 首次联网加载字体/CDN（断网自动降级）→ 双击 index.html，即得与本文档截图完全一致的画面。无构建、无依赖安装、无环境变量必填项。

5.2 演进链路（Git 提交 ↔ Prompt 一一对应）

开发全程 AI 协同，每次提交对应一个功能模块或一次核心对话（完整 Prompt 链见 docs/Prompt历史.md）：

提交模块AI 协同内容验证
001–002数据层 + 骨架/详情数据结构设计、视觉体系、素材统一风格截图 + DOM 断言
003问答引擎关键词匹配实现 → Bug① 拼接修复 → Bug② 揭示时序修复 → 思考状态补强15 类问题全命中回归
004地图与图谱力导向布局、标点偏移、键盘可达无头截图 + 无障碍检查
005沉浸 + 终版整合沉浸舞台、收藏、双主题、文创工坊8 视图全量回归
006性能优化7 项性能根因的修复链（见 4.2）自检 consoleErrors 全空

5.3 数据可追溯

15 项非遗内容基于国家级非遗名录与公开资料核对，不确定条目全部显式标注于"待核清单"（如批次表述、类别归属），数据诚实可溯源，拒绝编造。

5.4 防伪设计

  • 数据与视图分离：评委可逐条核对 data.js 的真实内容
  • 代码非拼接：8 视图由同一套数据模型与渲染函数驱动，无复制粘贴痕迹
  • Prompt 历史 + 演进记录 + 演示视频（含 ≥2 分钟 AI 协同复现）三证齐备
