## 一、项目详情及使用方式

### 1.1 作品定位

非遗知识散落在官方名录、地方志和短视频里，存在三个现实问题：**难查**（条目分散、缺乏统一入口）、**看不懂**（专业口径与大众表达之间有距离）、**没兴趣**（纯文字名录缺少可交互的呈现方式）。本作品面向这一痛点，做一个"能看、能问、能关联、能生成、能沉浸"的河南非遗数字展厅：用户从首页进入，浏览展品总览，点进详情页阅读讲解，通过问·AI 追问深挖，收藏感兴趣的条目，最后生成本地文创海报分享。

作品收录 **25 项河南国家级非遗**，覆盖戏曲、技艺、美术、民俗、曲艺、体育 **6 个门类**，分布在 **13 个地市**；藏库另设 **15 件**代表性藏品，配 **10 段**表演类讲解音频与 **15 件**工艺流程图文。全站共 **10 个视图**：首页、展品总览、详情页、非遗地图、城市介绍、知识图谱、问·AI、文创生成、沉浸演绎、演进馆。

### 1.2 运行方式（三种，按评审场景选择）

**方式一：单文件产物（评审推荐）**

仓库不内置打包产物（`dist/` 已在 `.gitignore` 中排除），克隆后执行一条打包命令即可生成可演示的单文件 HTML：

```bash
git clone https://github.com/linchenan666/feiyi-zhihui.git
cd feiyi-zhihui
py -3 scripts/bundle_single.py        # Windows；macOS / Linux 用 python3 scripts/bundle_single.py
```

打包完成后，双击打开：

```
dist/非遗智汇·多彩面板版.html
```

全部 JS、数据、图片、字体、音频都已内联到这一个 HTML 文件中，**不需要本地服务器，不需要联网**，用 Chrome / Edge 114 及以上版本直接打开即可。

**方式二：源码多文件版（便于阅读与调试）**

直接双击仓库根目录的 `index.html`，依赖同目录下的 `assets/`、`vendor/` 与各 `*.js` 文件，适合查看模块化源码。

**方式三：本地静态服务（仅接入在线大模型时需要）**

```bash
py -3 -m http.server 8000
# 浏览器访问 http://localhost:8000
```

`file://` 协议下浏览器会拦截 `fetch`，只有在填写在线大模型接口时才需要起本地服务；默认离线模式不使用该方式。

## 二、项目亮点

### 2.1 离线优先：断网功能完整，零第三方网络请求

作品把"断网可跑"作为硬约束贯穿始终。three.js、OrbitControls、Lenis 等第三方库在开发阶段就下载到本地 `vendor/` 目录；字体、图片、讲解音频在打包阶段全部转成 base64 data URI 内联进单文件。运行时不向任何第三方域名发请求，评审现场没有网络、网络受限或断网状态下，页面、3D 场景、问答、音频、图谱、地图均能正常工作。

### 2.2 真 3D 展柜 + 榫卯拆解：程序化 WebGL，不是图片加动画

藏库中四件展品提供可交互的真 3D 场景，全部由 three.js **程序化几何生成**，不依赖外部 glTF 模型资产：

| 3D 场景 | 几何实现 | 交互 |
|---|---|---|
| 汝瓷天青碗 | `LatheGeometry` 旋转体 | 轨道旋转 / 缩放 / 平移、天青·粉青·月白三材质切换、双击复位 |
| 钧瓷窑变花浇 | `LatheGeometry` 旋转体 | 同上 |
| 唐三彩三足罐 | `LatheGeometry` 旋转体 | 同上 |
| 榫卯拆解 | 两个 `BoxGeometry`，一件带榫头、一件带卯眼 | 滑块 / 按钮控制"拆开 ↔ 复位"，沿轴向位移形成爆炸视图，带榫头 / 卯眼结构标注 |

场景采用懒初始化，离开视图即调用 `dispose()` 释放几何体、材质与 WebGL 资源，避免内存泄漏。选榫卯作为拆解演示对象，是因为木作榫卯本身属于国家级非遗，其本质就是装配与拆解，与展厅主题直接对应；两个木块完全由代码生成，零模型文件。其余 11 件藏品不显示 3D 入口，走实物影像 + 讲解词，避免为凑数量做虚假 3D。

### 2.3 双层 AI：本地知识库兜底，大模型接口预留，不夸大能力

问·AI 模块采用双层结构：

- **离线层（默认）**：`data.js` 内置 `KB_ALL` 问答对，关键词打分匹配，支持多轮上下文指代消解——例如先问"汝瓷为什么叫雨过天青云破处"，再追问"它的产地在哪"，系统能自动回指上一主题。纯本地作答，断网演示不断线。
- **在线层（可选）**：`app.js` 顶部 `REMOTE_API` 预留兼容 OpenAI Chat Completions 协议的接口，填齐地址、Key、模型并打开开关后，回答切换为大模型生成；不填时界面不出现在线切换按钮。

作品在界面与文档中均明确标注：**默认回答来自内置知识库检索匹配，并非大模型生成**，不把关键词匹配包装成 AI 大模型。

### 2.4 25 项条目事实口径复核，关键信息对照官方名录标注

条目内容以国家级非物质文化遗产代表性项目名录与公开资料为依据整理。关键事实——类别、批次、申报地区、产地、窑址——对照中国非物质文化遗产网（ihchina.cn）官方名录复核，例如：汝瓷产地表述为"宋代属汝州辖境，今窑址在宝丰清凉寺"，历史地名与考古窑址分开写；唐三彩申报地区统一为洛阳，巩义标注为窑址考古地；汝瓷保留"五大名窑之首"口径，钧瓷改为"五大名窑之一"；年代类表述加"相传""约"等限定词。数字化复原件、AI 示意图、仿品图统一标注"示意 · 非原物"，3D 场景内标注"数字化复原示意，非文物扫描"，不把示意图冒充实拍或文物扫描件。

### 2.5 图片版权分级合规，风险图片全部处置到位

开发后期对全部图片做过一次版权审计，按来源分级处置：

- 商业图库渠道化命名的源图直接删除，并加入 `.gitignore`，不进入版本库；
- 未取得授权的媒体机构图源替换为 AI 生成示意图；
- 无来源记录的招牌主图统一替换为 AI 工笔淡彩示意图，数据项补 `replica: true`，前端自动渲染"示意 · 非原物"角标；
- 博物馆官网、文旅局、院团公开资料来源的图片保留，并在 `note` 字段补录出处；
- README 设独立的"图片来源与许可声明"章节，说明非营利参赛与教学用途，并保留 Issue 联系更换 / 下架通道。

数字讲解员形象为 AI 生成的虚拟人物，不对应真实自然人；所有影像压缩到展示分辨率后内联，高清原件不随作品分发。

## 三、AI 测试技术落地使用情况

### 3.1 开发模式：豆包 Vibe Coding 全流程协同

本作品全程使用豆包进行 Vibe Coding 协同开发，覆盖从需求解构、模块实现、迭代打磨到 Bug 修复、合规审计的完整过程。112 次 Git 提交中，每次提交对应一个功能模块或一轮核心 AI 对话，没有用一次初始提交堆完全部功能，评委可通过 `git log` 对照 `docs/Prompt历史.md` 逐条复核。

### 3.2 Prompt 工程：先给上下文，再提需求

实际协同中形成了三条固定做法：

1. **上下文先于提问**：每轮对话开头先交代项目定位（纯本地、零后端、单文件、断网可跑）、数据位置（`data.js` 的 `FEIYI_DATA` 数组与现有字段结构）、硬约束（配色体系、字体内嵌、hash 路由、零 CDN），让 AI 不靠猜测产出代码。
2. **架构约束写进每一轮**：数据层只写数据不操作 DOM，视图层只渲染不写业务逻辑；不允许引入外部 script / link；所有依赖进本地 `vendor/`。这些约束在后续每轮 Prompt 中重复强调，避免 AI 在新上下文里重新引入 CDN 或自创字段。
3. **一轮只做一个功能**：按模块拆分需求，一次对话聚焦一个视图或一个问题，模块边界清晰后再进入下一轮，避免一次性塞入全部需求导致代码失控。

### 3.3 迭代与 Bug 修复：人工审查 → 指出问题 → AI 修复 → 再验证

AI 产出后由人工审查，发现问题后引导修复，再回到浏览器实测验证，每轮记录"我要什么 → 我对 AI 说 → AI 给的方案 → 结果如何"四步。开发过程中修复过的典型问题包括：

- **关键词拼接导致问答 0 命中**：知识库关键词数组由整句拼接、未分词，单项目名和短问题匹配不上；改为项目名与问题分词结果的并集后，三类测试问题全部命中。
- **打字机定时器跨视图泄漏**：流式回答在切换视图后未停掉定时器；统一在视图切换时停止隐藏视图的常驻定时器。
- **窄屏知识图谱被压缩**：移动端适配时把 1000px 图谱压到 390px，节点文字不可读；回退后固化"窄屏最小物理宽度 + 横向滚动"规则。
- **深色背景下收藏按钮不可见**：灰色图标在墨色背景上点击后消失；改为常显朱砂色实底，状态切换保留图标。
- **多轮追问指代失效**：补充汝瓷、钧瓷、唐三彩"产地"问答对，并完善上下文回指逻辑，"它的产地在哪"能正确命中当前主题。

### 3.4 三重思维检查：每轮交付前过一遍

每个模块落地前，按三个维度做交付前自检：

- **技术可行性**：离线渲染性能是否达标、WebGL 资源能否释放、窄屏是否可读、断网是否功能完整；
- **内容深度**：条目讲解是否有要点、深挖方向与考据点，问答是否覆盖真实追问场景，不做只有标题的空页面；
- **工程合规**：是否真离线、依赖是否本地化、图片版权是否处置到位、事实口径是否与官方名录一致、代码是否有 XSS 与资源泄漏风险。

### 3.5 三条核心迭代链（证据可对照 Git 提交）

| 链 | 主题 | 过程 | 对应提交 |

## 四、关键技术

### 4.1 three.js 程序化 3D，零外部模型资产

three.js r186 与同版 OrbitControls 入库 `vendor/`，打包时内联，不引用 CDN。四件 3D 场景全部使用 `LatheGeometry`（三件旋转体器物）与 `BoxGeometry`（榫卯两木块）程序化生成，不加载 glTF / Draco 高模；场景懒初始化，关闭模态时 `dispose()` 释放几何体、材质与渲染上下文。3D 入口按藏品 ID 显隐，只对有真实场景的四件藏品显示。

### 4.2 base64 内联，单文件自包含

打包脚本依次内联 14 个本地 JS、子集化字体 CSS、56 张入库图片与 10 段讲解 WAV 音频，全部转为 data URI 写入同一个 HTML。产物为单个 `dist/非遗智汇·多彩面板版.html`，当前体积约 **30.73 MB**；运行时无外部资源请求，复制这一个文件即可在任意支持 WebGL 的浏览器环境中演示。

### 4.3 字体子集化内嵌

原始 Noto Serif SC / Noto Sans SC 全套字体体积较大，使用 fonttools / pyftsubset 按页面实际用到的汉字与符号子集化，输出 woff2 后 base64 内嵌，字体 CSS 约 **1,475 KB**；配合 `font-display: swap` 与系统字体回退栈，避免离线环境白屏。

### 4.4 本地知识库问答与多轮指代

离线问答基于 `KB_ALL` 问答对做关键词打分匹配，命中阈值与兜底话术在 `app.js` 中实现；维护最近一轮主题，对"它 / 这个 / 那"等指代词回指上一非遗条目，支持跨轮追问。所有问答内容来自本地数据文件，不依赖远程服务。

### 4.5 幂等构建脚本，失败即停

`scripts/bundle_single.py` 只用 Python 标准库（`io`、`os`、`re`、`sys`、`base64`、`urllib`），不写时间戳、不写随机数，同一份源码重复运行产物字节一致，可通过连续两次运行比对 SHA256 验证。脚本内建前置校验：文件缺失、藏品 / 音频 key 数量不齐、图片路径未内联等任一条件不满足，立即非零退出，不静默吞错，也不会产出一个看似完整、实则残缺的单文件。

### 4.6 架构分层与工程细节

- **数据 / 视图分离**：`data.js`、`map-data.js`、`regions-data.js`、`treasury-*.js` 为纯数据层；`app.js`、`treasury.js`、`three-showcase.js` 为视图与逻辑层；`index.html` 只承担结构与样式。新增非遗条目只需在数据层追加，首页统计条、图谱节点、地图标点、收藏计数由视图层自动计算。
- **hash 路由**：10 个视图通过 hash 路由无刷新切换，不使用前端框架，不经过构建打包。
- **XSS 防护**：用户输入与数据渲染前统一过 `esc()` 转义；收藏与分享文案不拼接未转义内容。
- **本地存储兜底**：收藏功能使用 `localStorage`，读写全部包 `try/catch`，存储不可用时降级为内存态。
- **性能控制**：指针动效单监听 + `requestAnimationFrame` 节流；隐藏视图的定时器即切即停；合成层 hover 才开启。
- **无障碍**：地图标点、图谱节点、收藏按钮键盘可达；提供 `prefers-reduced-motion` 兜底；页面使用语义化标签与必要的 `aria-label` / `role`。
