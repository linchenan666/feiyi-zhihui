## 链 2 · 问答引擎与 Bug 修复（Git 003）

### 2.1 功能提问

```
问·AI 视图：内置知识库离线问答。知识库数据放 data.js（KB_GLOBAL 总览条目 +
KB_ITEMS 项目条目），app.js 做关键词打分匹配：命中关键词 ≥4 字得 3 分、否则 2 分，
最高分 ≥2 才命中，否则走兜底话术。回答要流式打字输出，并标注答案来源。
```

**AI 产出**：`matchAnswer()` 打分匹配 + 打字机输出 + 来源标注。

### 2.2 发现 Bug ①：关键词拼接导致 0 命中

```
知识库问答有 bug：问"豫剧"和"钧瓷有什么特点"都命中不了。
排查：KB_ITEMS 的关键词数组是 [itemName].concat(question.split(" ")) 拼出来的
整句关键词，没有分词，所以单项目名或短问题都匹配不上。
请改成关键词数组 = [项目名] 与问题分词结果的并集，保证 15 个项目名、
问题片段都能命中；再验证"豫剧""钧瓷有什么特点""第一次来先看什么"三类问题。
```

**AI 产出**：关键词数组改为 `[item.name]` + 问题分词，修复后 15 类项目名问题全命中、无关问题走兜底。

### 2.3 发现 Bug ②：首屏空白的滚动揭示

```
动效升级后截图时首页空白：.rv 元素初始 opacity:0，IntersectionObserver
在快速导航/虚拟时间下没触发。要求：渲染后先检查元素是否已在视口内，
在视口内立即 .in 显现（跳过过渡），不在视口内的才交给 IO 观察。
```

**AI 产出**：`observeReveals()` 增加"视口内即时显现"分支，首屏不再依赖 IO 时序。

### 2.4 评审点名项的主动补强

```
评审标准里有一条"AI 响应状态提示友好（如流式、思考可视化）"。
问·AI 目前只有流式打字。请加"思考中"状态：用户发送后先出现三个呼吸点的
思考气泡（约 0.5s），再切换为流式作答；reduced-motion 用户直接出结果。
```

**AI 产出**：`pushMsg(thinking)` + `.think-dots` 呼吸动画 + 480ms 思考间隔，无障碍兜底。

## 链 4 · 性能优化（Git 006，第一轮真实 Bug 链）

### 4.1 问题报告

```
页面太卡了。排查重点：pointermove 监听、transform 过渡、合成层、定时器。
```

**AI 诊断与修复链**（每一行 = 一次 AI 修复 + 截图验证）：

| # | 根因 | 修复 |
|---|------|------|
| 1 | 3D tilt 每帧写 transform，被 CSS `transition:transform .35s` 拖着，永远滞后且持续重算 | tilt 激活时切 `transition:transform .1s ease-out`，离开还原 |
| 2 | 磁性 + tilt 两个 document pointermove 监听，无节流、每次强制同步布局 | 合并为单监听 `initPointerFX` + rAF 节流，每帧至多一次布局读 |
| 3 | header 毛玻璃 `backdrop-filter:blur(8px)` 滚动时逐帧重绘 | 移除 backdrop-filter，背景不透明度提到 .94 |
| 4 | 15 张卡片常驻 `will-change:transform`（15 个 GPU 合成层） | 改为 `.tilt:hover` 才开合成层 |
| 5 | Lenis rAF 循环在标签页隐藏时仍空转 | `visibilitychange` 暂停/恢复 |
| 6 | 沉浸轮播 / AI 打字机定时器离开视图不清理 | `showView()` 切换即 `clearInterval` |
| 7 | hero 视差写 `.hero-bg` 的 transform 与 kenburns 动画冲突（视差实际无效还在白写） | 外包 `.hero-bg-zone` 分层，动画与视差互不覆盖 |

**验证方式**：8 视图 Edge 无头截图全量回归 + `node --check` 语法 + 官方 shot.py 自检（consoleErrors 全空）。

## 链 6 · 滚动性能根治（M8.1–M8.2，ead0570 / 3fba5ae）

### 6.1 问题报告（用户实测两个独立症状）

```
打开页面进去之后，滑动的时候很卡，但是点击模块进入的时候是不卡的。
我用鼠标的滚轮来滚动的话还是卡，但是用鼠标拖拽进度条不卡。
```

**AI 诊断**：滚轮卡、拖进度条不卡 → 二者滚动路径不同——拖拽滚动条走浏览器原生合成滚动，而滚轮被 Lenis JS 插值接管：每帧用 `scrollTo` 写滚动位置，在"多张全屏大图 + 动效合成层"的复杂页面上逐帧驱动必然掉帧；点击模块切换不卡则佐证问题不在渲染而在滚动驱动层。

### 6.2 修复链（两轮提交）

| # | 动作 | 内容 |
|---|------|------|
| 1 | 动画收敛 | hero kenburns `26s infinite` → `14s forwards` 单次推近；沉浸轮播 `24s alternate` → `16s forwards`；移除常驻 `will-change` 合成层；鼠标视差滚动即清；滚动后隐藏"向下"指示（停动画） |
| 2 | 滚动引擎决策 | **禁用 Lenis**，回退浏览器原生硬件合成滚动（与拖拽进度条同一路径，零 JS 开销、滚轮手感最稳）；保留完整接入位（CDN 已引入，`RETURN_NOW=false` 一行启用），代码结构可演进 |

**决策记录（答辩要点）**：这不是"放弃平滑滚动"，而是基于实测的工程权衡——原生合成滚动由浏览器合成器接管，滚轮与进度条行为一致；Lenis 接入位保留，代码上随时可切回，属于可解释、可复现的性能决策。双端 console 无错、视觉零变化。

## 附 · Prompt 工程方法论（本文档提炼，供技术文档引用）

1. **上下文先于提问**：每次提问先给"项目是什么、数据在哪、约束是什么"，AI 不猜。
2. **把约束写进 Prompt**：视觉红线（禁 slop 套路）、性能红线（合成层/节流）、隐私红线（零第三方脚本）都以祈使句显式声明。
3. **Bug 报告三件套**：现象 → 我已排查的原因 → 期望行为。AI 一次定位、不瞎改。
4. **验证闭环**：每个功能提交前用无头浏览器截图 + 语法检查回归，发现问题立即补 Prompt 修复链。
5. **可复现性设计**：所有数据固化进 `data.js`、零环境依赖，评委双击即得同一画面。
6. **验收驱动扩散**：视觉改动每处独立提交 + 用户验收，通过才扩散；revert 保留为提交记录——"尝试→验收→收敛"本身是可信演进证据。
7. **真实素材优先**：外部图片逐张读图核验（内容对应、无水印）后才入库，绝不直接引用未核验的 URL。
8. **性能决策留口**：禁用 Lenis 等性能取舍保留接入位与决策记录，让每个"放弃"都可解释、可回切。
