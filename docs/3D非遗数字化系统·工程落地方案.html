0总纲：非遗是"无形技艺"，不是"有形器物"

非遗名录登记的是技艺，器物只是技艺的瞬时载体。只做"看得见的文物 3D"是对赛题的错误理解，也丢掉了展示系统的差异化价值。本系统强制三层结构，缺一层判不合格：

层回答的问题承载内容关键交互
L1 静态文物 3D器物长什么样（看得见）存档级高模 + 展示级优化模型、PBR 材质、色彩科学标定360° 观察、缩放、拆解、剖切、测量、热点标注
L2 工艺流程 3D 演示器物怎么做出来的（看得懂"怎么做"）工序序列化数据、零件/工具绑定、相机运镜、步骤动画逐步拆解、可暂停、可回到任意步骤、单步往复
L3 传承人口述与工艺知识为什么这样做（听得见"为什么"）口述录音、转写字幕、术语/材料/禁忌卡片、多语言语音随工序联动播放、语音导览、知识卡检索

三层的数据关系是绑定的，不是三个孤立模块：L1 装配树里的零件 id 被 L2 工序的 action 引用；L2 的每道工序被 L3 的口述片段引用。用户可以在任意一层发起跳转：点零件 → 看它在哪道工序生成；听口述提到"开料" → 跳到该工序的 3D 演示。

架构红线：三层全部离线可运行。L2 的工序动画和 L3 的口述音频必须与 L1 模型同包交付，不允许"模型本地、视频/音频在线"的偷工方案。

1.3 性能达成手段（对应上述目标）

  • 加载：渐进加载管线——先外壳（UI/清单）→ LOD0 网格 → 贴图（mipmap 渐进）→ 工艺/音频按需；gzip/brotli 压缩静态包。
  • 几何：LOD 三级（见 §2.2 面数表）；Draco 压缩（顶点 12bit 量化）；静态合批（同材质合并）；frustum + 八叉树遮挡剔除（展厅场景物件多时启用）。
  • 贴图：KTX2/BasisU（桌面 BC7、移动 ASTC）；纹理图集合并小贴图；LRU 释放离屏纹理。
  • 渲染：单次 draw call 预算——一体机场景 ≤600 draw call、≤120k 三角形（LOD 生效后）；后处理按载体开关（§3.3）。
  • 内存：显存纹理预算 ≤512 MB（一体机）；几何 ≤256 MB；不重复持有 glTF 原始 buffer（加载后即释放）。

2数据采集与建模工艺

2.1 原始数据获取：两条路线

路线 A：摄影测量（可接触、可拍摄的器物，主路线）

工具：RealityCapture 1.4.x（Epic 现行授权：非商业免费档 / 商业按收入分成；首选，对齐质量/速度最优）、Metashape 2.1.x（备选，Pro 单机授权）、Meshroom 2025（开源兜底，全流程免费，速度慢一档）。三套流程任选其一，输出同一规格：带控制点的对齐 + 密集点云 + 高分辨率网格 + 4K 纹理。

拍摄规范（现场执行单，逐条落实）：

项参数原因
机身/镜头全画幅或 APS-C；定焦 50–85mm 等效；手动对焦、焦点锁定变焦/自动对焦焦点漂移会直接废掉对齐
曝光光圈 f/8–f/11；快门 ≥1/125s；ISO ≤100；RAW 拍摄保证全物件景深清晰；ISO 压低噪点保证对齐与纹理
布光双柔光箱，光源面加线偏振片，镜头前加分析器旋转至正交（交叉偏振，消高光）；色温 5000K±200K，双灯强度一致消釉面/金属/漆面反光，拍出真实漫反射色；见 §2.3
转盘15°/帧（24 帧/圈）；俯角 0°/30°/60° 三圈 + 顶视圈 + 底部圈覆盖全部法线方向；小件共 120–200 张

标定物每圈首帧放置 X-Rite ColorChecker + 灰球（色卡占画面 ≥10%）色彩标定与白平衡的锚点（§2.3）

RealityCapture 处理参数：对齐精度 High；关键点匹配 ≥5000 对/帧对；对齐 RMS ≤0.3px、投影误差均值 ≤0.5px；控制点 ≥6 个、重投影误差 ≤1px；密集点云去噪（统计离群点，K=20, σ=2.5）；网格 Poisson 深度 12–14；简化用 Quadric Edge Collapse，误差上限 0.5mm（小件）/2mm（大件）。纹理：每 UV 岛 texel 密度 ≥20 px/cm（小件直接出 4K）。

路线 B：手工高模（不可接触 / 缺失部位补全，主路线之二）

工具：ZBrush 2025.x（细节雕刻）+ Blender 5.2 LTS（重拓扑、UV、装配、导出）。流程：文献线图/博物馆正摄影像/同型器物/传承人口述为复原依据 → 基模 → 雕刻细节（铸造范线、铭文、磨损用 alpha 笔刷与 brush 图层）→ 显式标注。

复原必须显式标注，不允许冒充实测：每个复原件在 glTF 扩展（自定义 KHR_x_hean_reconstructed 或 manifest JSON）记录：reconstructed: true、依据来源（文献/线图/口述/同型）、置信度（高/中/低）、参与确认的传承人/研究员。UI 渲染时给"复原部位"角标与半透明着色，点开即见证据链。这条同时是合规要求（§10 风险）与诚信要求。

2.3 色彩还原的科学管理（禁止肉眼调色）

目标：数字模型与实物并排比色 ΔE ≤ 3（CIEDE2000，D65/10°），覆盖釉色、漆色、金属锈色、木色四类材质。

2.3.1 硬件与链路

  • 取色：分光光度计 X-Rite Ci62（或 Konica Minolta CM-700d），每材质区 ≥5 点取均值，记录 L*a*b*；观察条件统一 D65/10°；输出到项目色值库（SQLite/CSV）。
  • 监视器标定：i1 Display Pro / Spyder X2 校色，D65、Gamma 2.2、亮度 120cd/m²；ICC profile 写入系统并锁死（禁用户侧改）。
  • 相机色彩链路：RAW 拍摄 → 灰卡白平衡 → ColorChecker 建相机 ICC（Lumariver Profile Designer 或 Adobe DNG Profile Editor）→ 去马赛克不做锐化 → 在 ICC 管理下转 sRGB。
  • 交叉偏振拍贴图：漫反射贴图用正交偏振（消高光）；另拍一张同机位同构图带高光参考帧（specular 参考），两图编号成对入档。

2.3.2 输出与记录

  • 工作空间：sRGB / Rec.709；金属件 baseColor 存线性 float（glTF metallic-roughness 金属通道不贴 sRGB 曲线），金属度/粗糙度用实测或目测分级（金属度 0.85–1.0，粗糙度 0.05–0.6 按打磨状态）。
  • 每件文物产出一份色值文档（入 manifest 元数据）：材质区名称、L*a*b*、对应 sRGB hex、metallic、roughness、clearcoat、实测点位数、取色日期、操作员。评审和复现都以此文档为准，而不是截图。
  • 抽样复验：每批次 ≥10% 材质区由第二人用 Ci62 复核，ΔE 漂移 >1 的区重做。

2.5 双轨：存档级 / 展示级

轨用途内容存储/保留
Master（存档级）长期保存、再加工、学术复现原始扫描网格/高模（500万–2000万面）、无损源贴图（TIFF/EXR）、摄影原片 RAW、色值库、复原证据链、口述母带 WAV/FLAC独立目录 assets/<id>/master/，只读归档；对象存储 + 异地备份；保留期永久

Unreal 5.6好引擎 + 着色器编译巨大（GB 级）Web 无支持；桌面影视级（Nanite/Lumen）但内存 2GB+商业分成否决：与离线轻量目标冲突

选定理由（一句话）：离线三形态（Tauri/PWA/自包含 HTML）要求单一代码库 + glTF 2.0/Draco/KTX2 全链路原生支持 + 包体可控 + 零授权成本，只有 three.js 同时满足；Babylon 的 WebGPU 领先与 Godot/Unity/Unreal 的桌面优势在本项目的"离线 Web 优先"约束下不构成收益。

3.2 渲染管线（参数固化）

  • API：WebGL2 基线（WebGPU 预留实验通道，不上线依赖）；渲染器 antialias:true、powerPreference:"high-performance"。
  • 光照：IBL 预烘焙环境（HDR 环境贴图 → irradiance + prefiltered specular，分光光度计标定色温匹配）+ 主光（方向光，强度 1.0–1.5）+ 填充 + 轮廓光；色温预设见 §4.6。
  • 材质：MeshPhysicalMaterial（metallic-roughness）；漆器/景泰蓝釉面启用 clearcoat（强度 0.6–1.0）；青铜锈区用多层贴图混合；各向异性仅景泰蓝金属丝区启用（cost 高，移动端关）。
  • 后期：ACES Filmic tonemapping（固定）；SMAA（桌面/一体机）；FXAA（低配）；bloom 仅桌面独显档可开（器物重点位，强度 ≤0.4）；SSR 不做。
  • 纹理：KTX2（桌面 BC7、移动 ASTC 4×4），mipmap 全开、各向异性过滤 8×（桌面 16×）。
  • 几何：Draco 解码放 Worker 线程；加载完成后释放原始 buffer。

3.3 性能手段（对应 §1.3 目标，逐条落到代码）

4交互与拆解系统

4.1 360° 观察与操控（L1 基座）

  • 轨道控制器：旋转（阻尼 0.08）、俯仰钳制 ±85°、缩放 0.05×–5×（相对物体包围盒半径）、平移、惯性；触屏单指旋转/双指缩放平移（pointer events 统一封装）。
  • 双击复位：回到标定初始机位；"初始视角"按钮常驻。
  • 交互层与渲染层分离：控制器只改相机状态对象，渲染循环消费；任何时刻可被拆解动画/工艺运镜接管并安全归还。

4.2 深度拆解：装配树 + 爆炸状态机

装配树 JSON 规格（每件文物一个，存 runtime 包）：

{
  "id": "mu-07", "name": "束腰攒框桌",
  "scaleUnit": "mm",
  "parts": [
    { "id": "top", "parent": null, "name": "面板",
      "explode": { "dir": [0,1,0], "dist": 320, "order": 5 }, "mesh": "top.glb" },
    { "id": "wedge", "parent": "leg", "name": "楔",
      "explode": { "dir": [0.7,0,-0.7], "dist": 90, "order": 1 }, "mesh": "wedge.glb" }
  ]
}

状态机：完整 → 拆解中 → 拆解态 → 回装中 → 完整，任一状态可暂停；explode(t) 按 order 顺序逐件位移（缓动 cubic-out，单件 0.4–0.6s，支持整体动画与单件步进）。操作：拆下一个 / 装回上一个 / 一键爆炸 / 一键复位；点任意零件可单独拖动（拖离/放回，带吸附回位）。榫卯类按真实拆卸顺序（先楔、穿带、再榫卯退位），顺序写进 explode.order，不是随意散开。

4.3 深度展示六件套

功能实现参数
剖切ClipPlane 六方向 + 自由平面（拖拽）；剖面双面渲染（背面法线翻转 + 剖面填充色材质）剖面填充色半透明 0.35；可多面叠加
透视 X-RayMeshBasic 全透 + 边缘光（fresnel 输出或后处理描边）透明度 0.08–0.15；边缘亮度可调
线框EdgesGeometry + LineSegments（顶点色），可与实体叠加显示线宽 1px，色随主题

5工艺流程演示层（L2：看得懂"怎么做"）

这是非遗系统与"文物扫描展示"的本质区别，权重最高。要求：每道工序逐步拆解、可暂停、可回到任意步骤；工序与零件/工具/口述三层绑定。

5.1 工序数据格式（每件文物一个 process.json，入 runtime 包）

{
  "id": "mu-07", "steps": [
    { "id": "s1", "title": "选料 · 开料", "duration": 8,
      "camera": { "from": [2,1.2,4], "to": [0.8,0.6,2], "ease": "cubic-in-out" },
      "actions": [
        { "t": 0.0, "type": "highlight", "ref": "top" },
        { "t": 0.5, "type": "label", "ref": "top", "text": "面板取材，顺纹避疖" },
        { "t": 2.0, "type": "audio", "ref": "tool-saw", "vol": 0.4 },
        { "t": 3.0, "type": "speech", "ref": "narr-s1", "lang": "zh" }
      ],
      "narration": { "text": "选料先看年轮走向……", "audio": "narr-s1.aac", "ts": [0,8] } }
  ] }
  • action 类型：highlight / label / explode / assemble / cut / audio / speech / part-visible；全部按相对步内时间 t 触发，播放器统一时钟驱动。
  • 相机运镜：关键帧（from/to）+ 贝塞尔缓动；每步默认 6–10s；运镜期间用户仍可拖拽查看（暂停运镜），松开后回到运镜路径。
  • 与 L1 绑定：ref 全部指向 §4.2 装配树零件 id；点"零件 → 它出现在哪道工序"由 process.json 反查索引生成。
  • 与 L3 绑定：speech 引用口述片段 id（§6），点口述卡可跳回对应工序。

5.2 播放器行为（验收即此清单）

  • 播放 / 暂停 / 上一步 / 下一步 / 回到任意步骤（步骤条点选）/ 循环单步往复。
  • 每步结束自动暂停（"可暂停"硬要求）；步骤条显示 已完成/进行中/未开始 三态。
  • 单步往复模式：当前步骤动画循环播（便于讲评），不自动进下一步。
  • 声音分层：口述（主）+ 工具声（环境）+ 工坊底噪（可选静音键全局）。
  • 全程离线：工序动画为本地 glTF/JSON 驱动，禁止用在线视频替代；确需视频素材（如传承人实拍）则转码内嵌（H.264 720p ≤10MB/段）并标注来源。

7离线打包与部署

7.1 交付形态三选一（对比 + 选型）

形态安装/体积跨平台维护与更新适用场景
Tauri 2.x（主推）壳程序 ~25–40MB（不含资源包）；资源外置随包Windows/macOS/Linux（WebView2/WKWebView/WebKitGTK）内置 updater（增量差分）；文件系统访问强，资源外置好做增量与校验展厅一体机、桌面工作站

7.2 断网可验证的打包方法与验证步骤

打包：

# 1) 构建 dist
npm run build                     # TS 编译 + 资源拷贝（assets/ 按 manifest 白名单）
node tools/make-manifest.mjs      # 生成 manifest.json（版本 + 每文件 sha256 + 语言包清单）
node tools/compress.mjs           # 纹理转 KTX2、音频转码、gzip/brotli 静态包
# 2) 校验
node tools/verify.mjs dist        # 校验所有 sha256，报告缺失/篡改
# 3) 三形态产物
npm run build:tauri               # → src-tauri/target/release/*.msi|dmg|AppImage
npm run build:pwa                 # → dist-pwa/（含 sw.js + precache manifest）
npm run build:html                # → dist-html/（index.html + assets/）

断网验证（四档，由快到慢）：

  1. DevTools 模拟：打开应用 → DevTools → Network → 勾选 Offline → 刷新 → 全功能走查（3D/拆解/工艺/口述/多语言）→ 零请求失败。
  2. 外部 URL 审计：对发布产物跑 rg -n "https?://" dist/，允许命中仅 data: 与相对路径；任何 http(s):// 资源引用即不合格（manifest 里允许放回传地址但必须可选关闭）。
  3. 真机断网：Windows 禁用网卡 / 手机飞行模式 → 完整走查一遍（含首启冷启动）。
  4. 本地服务 + 流量抓包：python -m http.server 8080 起服 → 打开 → Fiddler/DevTools 确认 0 个外部域名请求（字体、贴图、JS 全本地）。

7.3 离线更新机制

  • 增量更新包：客户端持 manifest.json（version + 每资源 sha256）；服务器/局域网推送新 manifest → 客户端 diff → 只下载变更资源（字节级差分，图片/音频用 bsdiff 或 xdelta3，模型走整文件）。
  • 推送通道：U 盘（导入工具校验 hash 后并入）、局域网 HTTP（内网静态服务）、Tauri updater（外网可选）。
  • 回滚：保留上一版 manifest + 资源目录，更新失败自动回滚。

7.4 资产防篡改

  • 资源加载前强制比对 manifest sha256，不一致拒绝加载并告警（防替换/注入）。
  • manifest 可选 Ed25519 签名（离线验签，公钥内嵌），面向正式发布。
  • 文物图暗水印（DCT 域，不可见），用于外泄溯源。

7.5 安全边界（评审关注项，直接写死）

面措施
XSS不 eval 外部输入；innerHTML 只用白名单模板；用户输入（搜索/批注）全部转义后入 DOM

7.6 失败容错（低配/异常路径）

  • WebGL2 缺失/初始化失败 → 自动切 2D 展品模式（每件备 ≤1MB JPG 展品图 + 图文说明）。
  • 资源加载失败 → 重试 2 次 → 跳过该项并提示 → 其余功能照常。
  • 内存不足（Performance.memory 阈值 80%）→ 强制 LOD1 → 释放离屏纹理（LRU）→ 提示降档。
  • FPS 持续 <20 五秒 → 自动降档（§3.3），不打断演示。

7.7 离线埋点与本地日志

  • 本地 JSONL 日志：view / action / duration / error / fpsSample / loadTiming，写入应用数据目录，滚动保留 90 天。
  • 联网时可选回传（默认关，设置页显式开启）：POST 脱敏聚合（无文物文件名、无设备标识），失败静默不阻塞。
  • 日志导出：提供"导出日志"按钮（JSON 打包），供维护与答辩举证。

10.3 数字资产长期保存与元数据标准

  • 元数据对齐 CIDOC-CRM（ISO 21127）：映射表——E22 Human-Made Object（文物）、E12 Production（制作事件，对接工艺层工序）、E67 Birth/E69 Death 不适用、E16 Measurement（尺寸/色值测量事件）、E89 Propositional Object（复原依据/文献）、E31 Document（授权与口述转写）。每件文物产出一份 cidoc.json（或 RDF 序列化），与 Master 轨共存。
  • 格式长期性：几何存档 glTF 2.0（开放标准）+ 原始格式双份；贴图 TIFF/EXR 无损；音频 WAV/FLAC；口述转写 TXT+JSON；禁止私有格式独存。
  • 备份策略：Master 轨双副本异地（如：馆方服务器 + 项目对象存储），季度校验 hash；版本只增不覆盖。
  • 可读性：目录规范 + 每目录 README（见 §3.4），换人不依赖个人记忆。

11三重思维检查（输出前自检结论）

第一重 · 技术可行性：离线渲染性能是否达标

结论：通过。首屏 ≤3s：本地资源零网络往返 + 渐进加载 + Draco Worker 解码（首屏只载 LOD0 与关键贴图，mipmap 渐进）；一体机 ≥30FPS：单场景 ≤600 draw call / ≤120k 三角形（LOD 生效），关后处理，KTX2 BC7 贴图显存 ≤512MB；单件 ≤50MB：LOD 三级 + Draco 8–12× + KTX2 4–6× 压缩在预算内（音频用 AAC 128k 控制）；总内存 ≤1.5GB：纹理 LRU + 几何不重复持有 + glTF buffer 用后释放。四项量化目标均有对应手段，无"拍脑袋"承诺。

第二重 · 交互与内容深度：是否覆盖五层"看全、看细、拆得开、讲得清、讲得出怎么做"

结论：通过。看全：360° + 缩放平移；看细：剖切/X-Ray/线框/热点/测量/光照预设（§4.3）；拆得开：装配树 + 爆炸状态机 + 逐件拆装 + 真实结构顺序（榫卯先楔再穿带）（§4.2）；讲得清：结构注释树 + 知识卡 + 口述（§4.4/§6）；讲得出怎么做：L2 工序演示层——逐步拆解、暂停、回到任意步骤、零件/工具/口述三层绑定（§5），这是本项目区别于"文物扫描展示"的核心，未省略、未降级。

第三重 · 工程质量与交付合规：是否真离线、可部署、可更新、可长期保存、合规闭环

结论：通过。真离线：打包产物外部 URL 审计为零 + 断网四档验证（§7.2）；可部署：Tauri 2 主形态 + 自包含 HTML 应急形态，共用 dist/manifest（§7.1）；增量更新：manifest diff + U盘/局域网推送 + 回滚（§7.3）；防篡改：sha256 强制校验 + 可选 Ed25519 + 暗水印（§7.4）；安全：XSS/本地文件/WebGL 注入三道边界写死（§7.5）；长期保存：Master 双轨 + CIDOC-CRM 元数据 + 开放格式 + 双副本备份（§10.3）；合规：授权清单门禁（§10.1）。
回炉项（开工前必须补齐，不补齐不进入 M1）：① 首批文物与馆方/收藏方的数字化授权尚未取得——这是所有工作的前置条件；② 四类文物各确认 1 件具体实物并出采集风险评估；③ 传承人口述授权书模板定稿。三项均为流程性前置，不阻塞方案本身，但阻塞开工。
