## 链 A · 图片版权合规

### 第一轮 · 版权审计（只出表，不动图）

#### ① 用户原话（提问）

> 你先别急着改图，你先帮我把图片的版权问题查一遍。然后把每个数据文件里的每张图的来源都进行读取一下，完事后给我一张表：文件名，来源，属于哪类，版权风险高不高，建议怎么处理。你先出表给我看，先别动图。

#### ② AI 回答 / 审计结果

通读 `data.js`、`treasury-real.js`、`treasury-data.js` 中全部图片的 `img` / `note` 来源字段，输出 20 张图的分类审计表，结论分三类：

| 类别 | 涉及图片 | 现状 | 风险等级 |
|---|---|---|---|
| 商业图库渠道化命名 | `assets/treasury_real/` 下 1688、视觉中国（vcg）、摄图网（shetu）等命名文件 | 来源为商业图库渠道，无授权证明 | 高 |
| 新华社图源 | `treasury-real.js` 中 zhuizi（坠子）、shaolin（少林）两张 | 媒体机构版权图，未取得授权 | 中 |
| 无来源字段 | `data.js` 15 张招牌图 + 唐三彩（sancai） | 无图源 / note 记录，无法追溯授权 | 高 |
| 博物馆官网 / 文旅局 / 院团 | 其余保留项 | 有公开出处可补录 | 低 |

**审计中识别的问题**：商业图库图不能留、新华社图不能直接使用、无来源图不能冒充实拍——三类硬伤，评委核查版权时会直接抓到。此阶段只输出审计表，未改动任何图片文件。

## 链 C · 真 3D 展柜 + 榫卯拆解

### 第一轮 · 从假 3D 到真 WebGL

#### ① 用户原话（提问）

> 现在这个 3D 珍品馆是有一些虚假的，就是图片加个动画结合起来的。我要真的能进行转动的 3D，用 three.js 进行做，能拖能缩能自动转，还要能拆开拼回去，全离线。

#### ② AI 回答 / 方案

1. **版本查证**：核查 three.js 最新稳定版本，选定 r186（0.186.1），源码下载到本地 `vendor/` 目录，全程离线加载，不引用任何 CDN；OrbitControls 一并本地化。
2. **路径对比**：给出两条可行路径——
   - 方案 A：程序化几何生成（LatheGeometry / BoxGeometry 等），零外部模型资产，体积小、可控、离线稳定；
   - 方案 B：外部 glTF 2.0 高模 + Draco 压缩，需要现成模型资产。
3. **首件实现**：汝瓷碗用 `LatheGeometry` 旋转体生成，配 OrbitControls 支持轨道旋转、缩放、平移与自动环绕；材质区分天青 / 粉青 / 月白；双击复位视角。

**审计中识别的遗留问题**：用户选定程序化方案后，"拆解 / 爆炸视图"需求不能省略；外部 glTF 高模路径暂缓，需要另找一个贴题、零模型资产的拆解演示方案。

---

### 第二轮 · 锁定两件藏品，补榫卯拆解

#### ① 用户原话（引导修复）

> 方案 A 还可以，B 暂时先不做，但拆解你不能给我省了，因为这是我最开始就要的，加榫卯拆解，两个木块带榫头卯眼，滑块控制拆开复位，榫卯本身是国家级非遗，本质就是拆装，是最贴题的。

#### ② AI 修复结果

1. **范围锁定**：方案 B（外部 glTF 高模）不做；本轮只交付两件程序化藏品——汝瓷碗 + 榫卯拆解。
2. **榫卯拆解场景**：两个木块用 `BoxGeometry` 程序化生成，一件带榫头、一件带卯眼；滑块（按钮）控制「拆开 ↔ 复位」，沿轴向位移过渡动画形成爆炸视图；场景内加「榫头 / 卯眼」结构标注。选榫卯的理由：木作榫卯本身是国家级非遗，比器物更贴题；榫卯本质即装配与拆解，天然适合演示深度拆解；程序化两个方块，零模型资产。
3. **工程约束落地**：场景懒初始化，离开视图即 `dispose()` 释放几何体、材质与 WebGL 资源，防止内存泄漏；全程零 CDN、零外部 glTF。
4. **接入现有藏库**：按藏品 id 显隐「3D 看器」按钮——仅汝瓷碗、钧瓷、唐三彩、榫卯四件显示 3D 入口，其余藏品走实物影像 + 讲解；modal 触发不破坏现有藏库功能。后续再补钧瓷花浇、唐三彩三足罐两个 LatheGeometry 旋转体场景。
